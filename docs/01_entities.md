# Анализ предметной области "Чудо Обувь"

# Функциональные требовония

1. В каталоге должно отображаться количество доступной обуви по моделям и размерам.
2. Для каждой модели обуви должно храниться изображение.
3. Пользователь может выбирать и заказывать несколько пар обуви.
4. Система должна показывать список заказов с датой и ФИО клиента.
5. Система должна поддерживать управление заказами.

## Роли пользователей

- Неавторизованный пользователь — просмотр каталога.
- Авторизованный пользователь — поиск товаров, фильтрация и оформление заказов.
- Менеджер — просмотр каталога, создание, просмотр и удаление заказов.
- Администратор — все функции менеджера и редактирование заказов.

## Авторизация

Вход выполняется по логину без пароля. Логин каждого пользователя должен быть уникальным.

## Поиск и сортировка

Товары можно фильтровать по категории и подкатегории, сортировать по цене и названию, искать по названию и производителю.


## Сущности и атрибуты

### 1. roles — роли пользователей
- role_id — идентификатор роли (PK)
- role_name — название роли

### 2. users — пользователи
- user_id — идентификатор (PK)
- last_name — фамилия
- first_name — имя
- middle_name — отчество
- login — логин
- role_id — роль пользователя (FK)

### 3. products — товары
- product_id — идентификатор (PK)
- category — категория
- subcategory — подкатегория
- manufacturer — производитель
- name — название
- image — изображение
- composition — состав
- description — описание
- price — цена

### 4. sizes — размеры
- size_id — идентификатор (PK)
- size_value — размер обуви

### 5. stock_items — товарные позиции
- stock_item_id — идентификатор (PK)
- product_id — товар (FK)
- size_id — размер (FK)
- quantity — количество

### 6. orders — заказы
- order_id — идентификатор (PK)
- order_date — дата заказа
- user_id — пользователь (FK)

### 7. order_items — состав заказа
- order_item_id — идентификатор (PK)
- order_id — заказ (FK)
- stock_item_id — товарная позиция (FK)
- quantity — количество
- unit_price — цена на момент заказа



## Связи между таблицами

1. roles → users (1:N)
   Одна роль может принадлежать нескольким пользователям.

2. users → orders (1:N)
   Один пользователь может оформить несколько заказов.

3. products → stock_items (1:N)
   Одна модель обуви может иметь несколько товарных позиций.

4. sizes → stock_items (1:N)
   Один размер может использоваться у разных моделей обуви.

5. orders → order_items (1:N)
   Один заказ может содержать несколько товаров.

6. stock_items → order_items (1:N)
   Одна товарная позиция может встречаться в разных заказах.

## Ограничения целостности

- При удалении заказа удаляются его позиции (ON DELETE CASCADE).
- Нельзя удалить товарную позицию, которая уже используется в заказе (ON DELETE RESTRICT).
- Нельзя создать заказ для несуществующего пользователя.
- Нельзя добавить в заказ несуществующую товарную позицию.

## Почему товарная позиция — отдельная таблица?

Одна модель обуви может иметь несколько размеров.
У каждого размера своё количество на складе.

Поэтому модель и размер связываются через stock_items.
Это позволяет хранить остатки отдельно для каждого размера.
