# Словарь терминов «Чудо Обувь»

1. Предметная область — часть реального мира, для которой создаётся система.
Пример: магазин обуви «Чудо Обувь».

2. Сущность — объект, о котором хранятся данные.
Пример: пользователь, товар, заказ.

3. Атрибут — характеристика сущности.
Пример: название и цена товара.

4. Первичный ключ (PK) — уникальный идентификатор записи.
Пример: product_id в таблице products.

5. Внешний ключ (FK) — поле, связывающее таблицы.
Пример: role_id в таблице users.

6. Связь — отношение между таблицами.
Пример: пользователь оформляет заказы.

7. Кардинальность — количество записей, участвующих в связи.
Пример: один пользователь может иметь много заказов (1:N).

8. Нормализация — организация таблиц для уменьшения дублирования данных.
Пример: товары и заказы хранятся отдельно.

9. Первая нормальная форма (1НФ) — каждое поле содержит одно значение.
Пример: размеры обуви не записываются списком в одной ячейке.

10. Вторая нормальная форма (2НФ) — все неключевые поля зависят от полного ключа.
Пример: остаток обуви зависит от сочетания модели и размера.

11. Третья нормальная форма (3НФ) — отсутствие транзитивных зависимостей неключевых атрибутов.
Пример: название роли хранится в roles, а не дублируется в users.

12. Транзитивная зависимость — зависимость одного неключевого поля от другого.
Пример: если в users хранить role_id и role_name, название роли зависит от role_id.

13. Аномалия вставки — невозможность добавить одни данные без других.
Пример: нельзя добавить товар без заказа, если всё хранится в одной таблице.

14. Аномалия обновления — ошибка при изменении повторяющихся данных.
Пример: фамилию клиента изменили только в одном из его заказов.

15. Аномалия удаления — потеря нужных данных при удалении записи.
Пример: при удалении последнего заказа исчезли данные клиента.

16. Товарная позиция — конкретная модель товара определённого размера.
Пример: Nike Air Force 1 размера 42.

17. Каталог — список товаров, доступных для выбора.
Пример: все модели обуви в магазине.

18. Справочник — таблица с повторно используемыми значениями.
Пример: roles и sizes.

19. Составной ключ — ключ, состоящий из нескольких полей.
Пример: сочетание product_id и size_id может однозначно определять товарную позицию.

20. Ссылочная целостность — правило, не позволяющее создавать неправильные связи.
Пример: нельзя оформить заказ на несуществующего пользователя.
