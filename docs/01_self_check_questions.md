# Вопросы для самопроверки

### 1. Почему товарная позиция — отдельная сущность?
Одна модель обуви может продаваться в разных размерах. Поэтому для каждого размера нужно отдельно хранить количество на складе.

### 2. Почему роль вынесена в справочник?
Чтобы не повторять название роли у каждого пользователя. В таблице users достаточно хранить role_id.

### 3. Почему цена хранится и в товаре, и в составе заказа?
В products хранится текущая цена обуви. В order_items сохраняется цена на момент покупки, чтобы старые заказы не менялись после изменения цены.

### 4. Почему итоговая сумма заказа не хранится в базе?
Её можно вычислить по товарам в заказе. Для этого количество каждой позиции умножается на её цену, а результаты складываются.

### 5. Что произойдёт, если удалить товар, который уже вошёл в заказ?
При правильно настроенных внешних ключах удаление можно запретить. Это необходимо, чтобы не потерять информацию о ранее оформленных заказах.

### 6. Что произойдёт, если два пользователя получат одинаковый логин?
Система не сможет однозначно определить пользователя при входе. Поэтому для поля login нужно установить ограничение UNIQUE.

### 7. Как схема защищает от аномалии обновления?
Повторяющиеся данные вынесены в отдельные таблицы. Например, название роли достаточно изменить один раз в таблице roles.

### 8. Какие ограничения целостности нужны на каждой связи?
Внешние ключи должны ссылаться на существующие записи. Например, нельзя добавить заказ с user_id, которого нет в таблице users.
