# Финальные ограничения базы данных

## Ограничения CHECK

| Таблица | Поле | Ограничение | Обоснование |
|---|---|---|---|
| products | name | CHECK (length(name) > 0) | Название товара не может быть пустым |
| products | price | CHECK (price > 0 AND price < 1000000) | Цена должна быть положительной и меньше миллиона |
| stock_items | quantity | CHECK (quantity >= 0) | Остаток не может быть отрицательным |
| order_items | quantity | CHECK (quantity > 0) | Количество в заказе должно быть положительным |
| order_items | unit_price | CHECK (unit_price > 0) | Цена позиции должна быть положительной |
| users | login | CHECK (length(login) >= 3 AND length(login) <= 20) | Длина логина от 3 до 20 символов |
| sizes | size_value | CHECK (size_value > 20 AND size_value < 50) | Размер обуви должен находиться в допустимом диапазоне |
| orders | order_date | CHECK (date(order_date) IS NOT NULL) | Дата должна распознаваться SQLite |

## Остальные ограничения

- PRIMARY KEY — уникальный идентификатор записи.
- FOREIGN KEY — связь между таблицами.
- NOT NULL — обязательное поле.
- UNIQUE — запрет повторяющихся значений.
- DEFAULT — значение по умолчанию.

## Вывод

Для базы данных shoe_store определены дополнительные ограничения целостности.

Они предотвращают добавление некорректных цен, размеров обуви, количества товаров и логинов.

Ограничения необходимо реализовать в db_init.py и проверить тестами.
