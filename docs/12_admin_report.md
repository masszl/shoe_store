# День 12. Администрирование SQLite

## Роли и права

В SQLite нет серверных пользователей и встроенных GRANT/REVOKE. Права реализованы на уровне Python-приложения: `admin_db` — SELECT, INSERT, UPDATE, DELETE, CREATE, DROP; `developer` — SELECT, INSERT, UPDATE; `reader` — SELECT. Функция `check_permission(conn, user_id, action)` читает роль пользователя и проверяет словарь PERMISSIONS. Проверка прав действует только для операций, проходящих через приложение; прямой доступ к файлу БД требует отдельной защиты.

## Резервное копирование

`backup_simple()` копирует файл через `shutil.copy2`, но при активной записи копия может быть несогласованной. `backup_safe()` использует SQLite Backup API и подходит для работающей базы. Скрипт создаёт оба вида копий в `db/backups`.

## Восстановление

Скрипт `maintenance.py` создаёт тестовую копию `restore_demo.sqlite`, удаляет в ней заказы и позиции заказов, затем восстанавливает её из безопасной резервной копии. Основная база при демонстрации не удаляется и не заменяется.

## Мониторинг

`PRAGMA integrity_check` проверяет целостность; ожидаемый результат исправной базы — `ok`. `PRAGMA page_size` и `PRAGMA page_count` дают размер базы в байтах. `sqlite_master` используется для списка таблиц.

## Результаты

Вставить фактический вывод `py src/maintenance.py`: результат integrity_check, список таблиц, размер базы, проверку ролей, пути резервных копий и количество восстановленных заказов. Если пользователи с ролями reader/admin_db отсутствуют, назначить роли тестовым пользователям и повторить проверку.
